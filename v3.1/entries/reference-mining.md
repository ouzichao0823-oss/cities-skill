# 入口 G: 参考文献挖掘与审核

## 触发

### 挖掘模式 — 从别人的论文里淘文献

用户说："挖一下这篇的参考文献"、"这篇论文里有什么对我们有用的"、"看看这篇引用了什么"、
"mining references from this paper"、"extract references from this PDF"、
"这篇的 reference list 里有没有值得追的"

### 审核模式 — 验证已写文本的引用是否真实

用户说："检查引用"、"参考文献靠谱吗"、"引用内容匹配"、"文献复查"、"citation audit"、
"审核引用"、"查一下你写的这些引用对不对"、"这个引用真的说了这个吗"、
"验证一下这段的文献支撑"

---

## 宪法状态要求

挖掘模式：宪法 §2（核心命题）和 §5（竞品坐标）须有内容。至少要知道"我们在研究什么"才能评分。

审核模式：待审核的文本须可追溯到宪法 §7（论证路线）的某个环节。
如果宪法是空的 → 先走入口 A 或 C 建立研究基础。

---

## 两种模式的关系

```
                    ┌──────────────────────┐
                    │    PyMuPDF 本地提取    │  ← 共享基础设施
                    │    CrossRef/PubMed    │
                    │    Zotero 去重        │
                    └──────┬───────────────┘
                           │
           ┌───────────────┴───────────────┐
           │                               │
           ▼                               ▼
   ┌───────────────┐              ┌───────────────┐
   │  挖掘模式       │              │  审核模式       │
   │               │              │               │
   │ 别人论文 →     │              │ 我们的文本 →    │
   │ 提取引用列表   │              │ 提取引用断言   │
   │ → 对比宪法评分 │              │ → 检索原文验证   │
   │ → S/A/B/C 推荐│              │ → 忠实度分级    │
   └───────────────┘              └───────────────┘
```

同一个基础设施，两个方向。挖掘是向外看（别人引了什么对我们有用的），审核是向内看（我们引的是否站得住）。

## 挖掘模式工作流

### 步骤 1: 获取论文全文

```
支持三种输入:
  - PDF 文件路径: 直接本地提取
  - DOI: 尝试获取摘要（开放获取的可以获取全文）
  - Zotero 中已有: 直接用本地 PDF 附件
```

### 步骤 2: PyMuPDF 本地提取

**不上传 PDF 到云端。** 所有文字提取在本地完成。

```python
import fitz  # PyMuPDF

def extract_text_from_pdf(pdf_path):
    """Extract all text from PDF locally. Returns full text string."""
    doc = fitz.open(pdf_path)
    full_text = []
    for page in doc:
        full_text.append(page.get_text())
    doc.close()
    return "\n".join(full_text)

def extract_references_section(pdf_path):
    """Extract the references/bibliography section from a PDF."""
    doc = fitz.open(pdf_path)
    full_text = []
    for page in doc:
        full_text.append(page.get_text())
    doc.close()
    text = "\n".join(full_text)

    # Find references section by common headers
    ref_headers = [
        "References", "REFERENCES", "Bibliography", "BIBLIOGRAPHY",
        "Literature Cited", "LITERATURE CITED", "参考文献",
        "References and Notes", "Notes and References"
    ]

    ref_start = -1
    for header in ref_headers:
        # Look for header as standalone line (possibly with numbering)
        idx = text.find("\n" + header)
        if idx == -1:
            # Try at start of text
            if text.startswith(header):
                idx = 0
        if idx != -1:
            ref_start = idx
            break

    if ref_start == -1:
        # Fallback: use last 30% of document
        ref_start = int(len(text) * 0.7)

    return text[ref_start:]
```

**提取原则**：
- 优先匹配 "References" / "Bibliography" 标题行
- 找不到 → 取文本后 30%（参考文献通常在末尾）
- **只提取 references 段，不读全文**（减少 token 消耗）

### 步骤 3: 解析引用条目

从 references 段中切分单条引用。处理常见格式：

```
识别模式（按优先级）:
  1. [1] [2] ... 编号格式（最常见）
  2. Author (Year). Title. Journal... APA/Harvard 格式
  3. 空行分隔的条目

逐条提取:
  - 作者（第一作者姓氏）
  - 年份
  - 标题
  - 期刊名
  - DOI（如可提取）
```

> **只做 best-effort 解析。** 不要求 100% 准确切分——即使部分提取，后续 CrossRef 搜索也能补齐。

### 步骤 4: 检索 + 去重

对每条解析出的引用：

```
1. Zotero 先查 → 已在库中的直接标记"已有"，跳到评分
2. 有 DOI → CrossRef 查摘要
3. 无 DOI → CrossRef title+author 搜索
4. 仍未找到 → PubMed 搜索（如涉及健康/环境）
5. 完全找不到 → 标记为"需手动查找"
```

Zotero 去重逻辑：
- DOI 精确匹配 → 已读
- 标题相似度 > 0.85 → 可能重复，列出让用户判断

### 步骤 5: 宪法驱动相关性评分

对每条成功检索到的引用，基于宪法评分：

```
评分维度（各 0-3 分）:
  A. 研究对象匹配: 研究对象/城市/人群是否和我们的一致或可比较？
  B. 议题匹配: 研究的议题是否和宪法 §2 的核心命题相关？
  C. 方法/数据价值: 是否用了我们可以借鉴的方法或数据？
  D. 竞品关系: 和宪法 §5 中已有的竞品相比，是补充还是重复？
  E. 理论贡献: 是否提供了可引用的理论框架或概念？

总分: 0-15
```

| 总分 | 推荐等级 | 含义 |
|------|---------|------|
| 13-15 | **S: 必须精读** | 直接竞品或方法可直接复用 |
| 10-12 | **A: 高度相关** | 重要参考，值得读全文 |
| 6-9 | **B: 背景脉络** | 和我们的研究有交叉，了解即可 |
| 0-5 | **C: 关联弱** | 可跳过 |

### 步骤 6: 输出推荐清单

```markdown

**来源论文**: [标题] ([作者], [年份])
**宪法上下文**: [§2 核心命题简述]

| # | 论文 | 为什么重要 | 与宪法的关系 | Zotero? |

| 1 | [Author (Year) Title. Journal.] | [具体理由] | [§5 新竞品/方法参考/理论来源] | 已有/需下载 |

### A 级: 高度相关

| # | 论文 | 相关点 | 建议用途 |
|---|------|-------|---------|
| ... | | | |

### B 级: 背景脉络

| # | 论文 | 交叉点 |
|---|------|-------|
| ... | | |

### C 级: 可跳过

共 X 篇关联较弱的引用，不逐条列出。

```

## 审核模式工作流

### 步骤 1: 提取引用断言

从待审核文本中提取 (断言, 引用标记) 对：

```
文本扫描:
  识别引用标记: (Author, Year), [1], [1,2,5], 上标数字等
  提取断言句: 包含引用的句子 + 其前后各 1 句
                → 形成"这个引用在支撑什么"的上下文
```

### 步骤 2: 逐条检索被引论文

同挖掘模式步骤 4（Zotero → CrossRef → PubMed）。

### 步骤 3: 论断分解

将待审核文本中「引文在支撑什么」的论断分解：

```
论断: "[我们的文本中写的这句话]"
必须拆解为:
  - claim (主张): 这句话在说什么事实/关系？
  - phenomenon: 什么现象？
  - entity: 什么对象/人群/城市？
  - relationship: 什么关系（增加/减少/相关/导致）？
  - context: 什么条件/背景下成立？
  - magnitude (如果有): 效果量是多少？
```

### 步骤 4: 内容比对

对比被引论文的实际内容（摘要，理想情况下全文）和我们的论断：

```
比对维度:
  □ 方向一致: 论文发现的方向（↑↓→）和我们的说法一致吗？
  □ 量级一致: 如果文本提到具体数字（如"23%增长"），论文报告的数字是这个吗？
  □ 对象一致: 论文研究的对象和我们说的一致吗（城市/人群/时间）？
  □ 关系强度一致: 论文说的是 correlation 但我们写成了 causation？
  □ 语境一致: 论文的发现是在什么条件下成立的？我们是否忽略了这个条件？
  □ 论文本身是否一手研究: 还是 review/opinion/perspective？（如果是 review，找到原始研究）
```

### 步骤 5: 忠实度分级

```
┌──────────────────────────────────────────────────────┐
│ ✅ exact-match      论文直接报告了我们所写的发现        │
│                     方向、量级、语境全部匹配             │
├──────────────────────────────────────────────────────┤
│ 🟢 substantial      论文支持总体方向，量级/语境有细微差异 │
│                     不影响主要论证                       │
├──────────────────────────────────────────────────────┤
│ 🟡 partial          论文支持部分论断，或发现相关但不相同   │
│                     需要调整措辞或补充引用                 │
├──────────────────────────────────────────────────────┤
│ 🔵 contextual-only  论文只提供了背景/框架，               │
│                     没有直接检验我们所说的关系             │
├──────────────────────────────────────────────────────┤
│ 🟠 overstatement    我们把论文的发现说得比实际更强         │
│                     "suggests" → 写成了 "demonstrates"  │
│                     "correlation" → 写成了 "causes"      │
├──────────────────────────────────────────────────────┤
│ 🔴 mismatch         论文的发现和我们写的矛盾或不相关       │
│                     必须删除此引用或重写文本               │
├──────────────────────────────────────────────────────┤
│ ⬜ unverifiable     无法验证（无摘要、付费墙、              │
│                     非英文、找不到全文）                   │
└──────────────────────────────────────────────────────┘
```

### 步骤 6: 输出审核报告

```markdown
## 引用内容忠实度审核报告

**审核范围**: [文本来源 — 引言第2段 / 讨论§文献对话 / 全篇]
**审核时间**: [DATE]
**审核标准**: 被引文献的实际内容 vs 文本中断言的匹配程度

---

### 总览

| 总计 | ✅ exact | 🟢 substantial | 🟡 partial | 🔵 contextual | 🟠 overstate | 🔴 mismatch | ⬜ unverifiable |
|------|---------|---------------|-----------|-------------|-------------|-----------|-------------|
| N    |         |               |           |             |             |           |             |

---

### 🔴 需要立即处理 (mismatch / overstatement)

| # | 文本中断言 | 引用 | 问题 | 证据 | 建议 |
|---|----------|------|------|------|------|
| 1 | "[原文]" | [Author (Year)] | mismatch: 论文实际发现的是X，文本写的是Y | 摘要: "..." | 删除此引用，替换为... |

### 🟡 需要调整措辞 (partial / contextual-only)

| # | 文本中断言 | 引用 | 问题 | 建议 |
|---|----------|------|------|------|
| 1 | "[原文]" | [Author (Year)] | 论文只报告了A，文本扩展到B | 改为 "While [Author] found A in [context], whether this extends to B remains unclear" |

### 🟢 通过审核 (exact / substantial)

共 N 条。不再逐条展开。

### ⬜ 无法验证

| # | 引用 | 原因 | 建议 |
|---|------|------|------|
| 1 | [Author (Year)] | 付费墙 | 建议从 Zotero 获取 PDF 后重新审核 |

---

### 系统性发现

[如果多条引用出现同类问题，在此总结。例如:
 "讨论部分有 4 条引用将相关性表述为因果性——这是系统性的 overstatement。"]

### 宪法更新建议

[审核结果是否影响:
 §2 核心命题的支撑强度？
 §5 竞品坐标的准确性？
 §3 理论透镜的适用范围？]
```

## 双模式共通规则

### Zotero 优先原则

同宪法原则 #5：任何引用的文献，先查 Zotero 是否已有。已有 PDF 的 → 可以直接读全文进行验证。

### 检索优先级

```
1. Zotero 本地库（含 PDF 附件）
2. CrossRef (DOI → 元数据 + 摘要)
3. PubMed (生物医学/环境健康方向)
4. 告知用户需手动获取（付费墙/找不到）
```

### 摘要的局限性（必须告知用户）

```
⚠️ 重要提醒:

基于摘要的审核是初步筛查，不是最终结论。

摘要的常见问题:
  - 许多论文的摘要不报告具体效应量
  - 摘要可能省略边界条件和方法论限制
  - 摘要用词可能比正文更强或更弱
  - 负面结果/不显著发现常不出现在摘要中
  
因此:
  - 🟢 exact-match 的判定从摘要层面是保守的（可能实际上更匹配）
  - 🔴 mismatch 的判定相对可靠（摘要不会说和正文相反的发现）
  - 🟡 partial 和 🟠 overstatement 需要读全文才能最终确定
  
  → 对标记为 partial/overstatement 的引用，建议从 Zotero 获取 PDF 全文后重新审核。
```

### 数量控制

```
挖掘模式:
  - 论文引用数 < 50: 全量评分
  - 论文引用数 50-100: 第一轮先筛 S/A 级 → 问用户是否继续筛 B/C
  - 论文引用数 > 100: 先只做 S 级 → 问用户是否继续

审核模式:
  - 引用数 < 20: 全量审核
  - 引用数 20-50: 分批次，每批 ~15 条
  - 引用数 > 50: 先做"快速筛查"（只看 mismatch 和 overstatement）
```

## 宪法更新

挖掘或审核完成后，检查宪法是否需要更新：

```
□ §5 竞品坐标 — 发现了新竞品？→ 加入表格
□ §2 核心命题 — 引文内容是否动摇了命题的支撑？→ 调整锋利度或措辞
□ §3 理论透镜 — 发现了新的理论资源？→ 记录
□ §8 循环日志 — 记录本轮操作和发现
```
