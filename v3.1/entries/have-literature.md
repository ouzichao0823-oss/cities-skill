# 入口 C: 我读了文献 → 竞品定位与 Gap 结晶

## 触发

用户说："我读了一些论文"、"这些论文和我的研究有什么关系"、"我的 Gap 是什么"、"感觉别人都做过了"

## 宪法状态要求

至少 §1(种子) 和 §3(理论透镜 tentative) 有内容。否则先走入口 A。

---

## 核心原则

"我读了文献" ≠ "我做了文献综述"。文献综述的功能是**定位**，不是**罗列**。

大多数小白的困境：读了很多论文，但不知道它们在"拼图"中的位置。这个入口就是帮你把散落的论文拼成地图。

---

## 步骤

### 1. 论文拆解

对用户提到的每篇论文，提取其逻辑链：

```
论文: [Author, Year]
  对象: [他们研究了谁/什么]
  议题: [他们回答了什么学术问题]
  数据: [他们用了什么数据]
  方法: [他们用了什么方法]
  核心发现: [一句话]
  理论透镜: [他们用什么理论在看这个问题?]
  
  这篇论文在你的拼图中的位置: [方法参考 / 竞品 / 背景 / 理论渊源 / 不相关]
```

### 2. 构建竞品矩阵

把拆解的论文填入矩阵：
> 参考 `core/positioning.md` 的框架。

```
横轴: 论文
纵轴: 逻辑链各环

        论文A  论文B  论文C  论文D  你的研究
对象     [x]    [x]    [~]    [ ]    [x]
议题     [x]    [~]   [ ]    [~]    [x] (或更新的)
数据     [~]    [x]    [x]    [ ]    [x] (或更细的)
方法     [x]    [ ]    [x]    [ ]    [x] (或组合)
城市     [x]    [~]   [x]    [~]    [新城市/多城市]

[x]=相同 [~]=相似 [ ]=不同
```

### 3. 识别 Gap 类型

> 核心参考：`core/literature-review.md` 的 Gap 分类。

| Gap 类型 | 你的情况 | 审稿人怎么看 |
|---------|--------|------------|
| **文献线未交叉** | A线成熟，B线成熟，但从未有人连接A+B | "novel synthesis" — 中等风险，高回报 |

> ⚠️ **[DATE] 真实语料核查**：这是**贡献类型**（novel synthesis 确实是真实存在的贡献），但不是 **Gap 句写法**——真实论文的 Gap 句几乎全是单线推进式（传统聚焦 A → 忽视/缺陷 B → 本文做 C），"A线成熟+B线成熟+从未有人连接"的结构在真实语料中不存在。Gap 句写法详见 `journals/cities/01-introduction.md` 第二节 2.2 小节。
| **新语境检验** | 已有机制在中国/你的城市未被验证 | "extending theory to new context" — 低风险，中回报 |
| **新数据回答老问题** | 你的数据粒度/时间跨度有质的优势 | "using novel data" — 低风险，中回报 |
| **新方法揭示新维度** | 已有方法不能捕捉你的现象 | "methodological advance" — 高风险，高回报 |
| **新问题** | 你问了一个没人问过的问题 | 最高风险 — 必须论证为什么你的问题值得问 |

### 4. Gap 精确陈述

> 直接使用 `core/literature-review.md` Layer 3 的模板。

```
"Prior work has [established/documented] [A] using [method/data] in [context] (refs),
and separately shown [B] (refs).
However, [the gap — what connects A and B, or what A implies for new context,
or what existing methods cannot capture].
This is important because [why filling this gap changes something]."
```

### 5. "感觉别人都做过了"怎么办？

这是一个如此常见的困境，需要专项诊断：

| 可能的原因 | 诊断 | 解法 |
|----------|------|------|
| 你不知道自己的数据/方法比已有文献好在哪 | 对比粒度不够 | 回到入口B，做精细的数据能力画像 |
| 你看的是同一个议题的大方向，没注意到细分 | 议题没拆解 | 回到入口A，在 `themes/` 中找子议题 |
| 你看到了类似论文但没有做竞品矩阵 | 缺少结构化的对比 | 做 §2 的竞品矩阵——通常会发现问题 |
| 你的 Gap 确实是小的，但合法 | 不要恐慌 | 新语境检验 + 新数据 = 合法的Q1贡献 |
| 你的文献搜索范围太窄 | 多搜 | 使用 `nature-academic-search` 跨数据库检索 |

---

### 6. 环境特调文献验证（2026-07 新增）

当用户已完成初稿、需要验证文献支撑时，启动三层交叉验证：

```
Layer 1 — 引文存在性检查
  对论文中每条 (Author, Year) 引用:
    → Zotero MCP (<ZOTSEEK_PORT>/mcp): 按作者姓+年份检索，读回 title/journal/date/DOI
    → 标记: ✅已入库 / ⚠️未入库需补充 / ❌库中有但匹配错误
    
Layer 2 — 主张-文献支撑映射
  对论文中每个有事实性主张的句子:
    → ZotSeek MCP: 语义检索最相近的段落
    → 本地句子比对工具: 句子级验证主张是否有文献支撑
    → 标记: ✅有直接引用 / ⚠️有相近引用但非精确匹配 / ❌无支撑

Layer 3 — 竞品坐标闭合性
  宪法 §5 竞品坐标中的论文:
    → 逐篇检查是否在引言和讨论中都被引用
    → 引言出现但讨论消失 → 需补入讨论
    → 讨论出现但引言未出现 → 需补入引言或从讨论删除
    → 宪法 §5 有但论文全篇未出现 → 严重疏漏
```

**非主题句文献验证规则**：

非主题句（段落中间的解释句、机制推测句、背景铺垫句）最容易缺文献。每段标注：
- **T** (Topic sentence): 段首句，宣告段落论证方向
- **E** (Evidence sentence): 引用文献支撑的句子
- **I** (Interpretation sentence): 作者自己的解读，不强制需要引用
- **C** (Claim without citation): 事实性主张但无引用 → **必须补充**

**环境工具映射**：
| 验证任务 | 工具 | 命令/端点 |
|---------|------|----------|
| 引文入库验证 | Zotero MCP | `http://127.0.0.1:<ZOTERO_MCP_PORT>/mcp` |
| 段落级语义验证 | ZotSeek MCP | `http://localhost:<ZOTSEEK_PORT>/zotseek/mcp` |
| 句子级精准定位 | 本地句子比对工具 | 本地服务 |
| 缺漏文献补充 | nature-academic-search | Skill 桥接 |

---
## 输出

1. 论文拆解（每篇的逻辑链）
2. 竞品矩阵
3. Gap 类型判断 + 精确陈述
4. **宪法写入**：竞品坐标、Gap 类型、贡献声明、逻辑链中相关环更新为 confirmed
5. **文献支撑审计报告**（如已进入写作阶段）：引文存在性、主张-文献映射、非主题句缺口、竞品闭合性
