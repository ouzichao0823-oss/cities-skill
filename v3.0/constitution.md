## §0 工作原则 (Working Principles)

```
1. 用户提出新解释/改动 → 优先更新本宪法，正文按新解释重写，不迁就旧文本。
2. 版本后缀管理：每次交付新文件（_vN），旧版本保留不覆盖。
3. 引用纪律：唯一来源 = 你的 Zotero 库。任何文献引用在写入正文/宪法之前必须
   查库核验（MCP/ZotSeek，用标题关键词而非仅作者年份）；库中查不到 = 该引用不存在，
   立即删除或替换，禁止以"待核/身份待核"形式长期挂账。写完跑引用审计（EXACT/
   SUBSTANTIAL/PARTIAL/OVERSTATEMENT/MISMATCH/UNVERIFIABLE），不挂羊头卖狗肉。
   待办/状态中的文献条目必须带核验标记：✅=已查库有条目 ⚠️=未核验（当天必须核验
   或删除，禁止跨会话遗留 ⚠️ 条目）。
4. 交付物：明确路径 + 改动用 🔴 标注 + 中英对照（用户需要时）+ 完整核验表。
5. 批注纪律：去破折号（英文术语如 job–housing 除外）；英文引用尽量不放在句首；
   中文不用"即"句式；gap 客观中肯，禁绝对否定。
6. 主题句纪律：每段主题句=一句平实的话说明"这一段在说什么"，读者只看主题句
   即知论文大致内容；段间由主题句形成递进。
```

## §2 核心命题 (Thesis Statement)

```
状态: seed / refined（初始为 seed，随研究推进升级为 refined）

[一句话命题：核心变量 —— 其操作性定义 —— 构成什么现象的什么角色。
它挑战或修正了既有文献的哪个默认假设？]

[一句话经验预期：在[你的样本/案例]中，[核心变量]如何分化出质上不同的[结果]。]
```

> **锋利度检查**：这句话能否让同行说"我想知道是不是真的"？
> 一个好的命题应当同时具备理论上的挑战性与经验上的可检验性。
