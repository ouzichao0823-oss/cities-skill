# 入口 B: 我有数据 → 数据能回答什么层级的问题

## 触发

用户说："我有XX数据"、"能不能用XX数据做YY"、"这个数据能做什么"

## 宪法状态要求

至少 §1(种子) 有内容。如果宪法完全为空，先走入口 A。

---

## 核心原则

**数据不是"你有什么就做什么"，而是"你的数据为什么是回答这个问题的必要条件"。**

不要问"这个数据能做什么"（太宽），要问"这个数据在什么研究设计模式中是不可替代的"。

---

## 步骤

### 1. 数据画像

识别用户数据的"能力边界"：

```
数据名称: [用户描述]
数据粒度: [个体/家庭/网格/街道/城市? 时间频率?]
数据覆盖: [空间范围? 时间跨度? 样本量?]
关键变量:
  - 可直接获得: [列出]
  - 可间接推断: [列出 + 推断方法的可靠性]
  - 无法获得: [列出 — 这决定了你不能回答什么问题]
```

### 2. 能力边界 → 可回答的问题层级

| 数据能力 | 能回答什么层级的问题 | 不能回答 |
|---------|-----------------|--------|
| 有人口属性+位置 | 空间分异、隔离测度、群体比较 | 因果机制（除非有时间维度） |
| 有位置+时间序列 | 移动模式、活动空间、职住关系 | 主观感受、出行目的（需推断） |
| 有政策/事件节点 | 准实验设计(DID/Event Study) | 连续变化的效应（除非有面板） |
| 只有横截面 | 关联分析、空间格局描述 | 因果关系、变化趋势 |
| 有面板/重复截面 | 因果推断、动态变化 | —（优势） |
| 有文本/图像 | 感知测度、叙事分析、分类 | 全量统计推断（除非+结构化数据） |

> 加载 `core/design-patterns.md` 获取更多数据-模式匹配逻辑。

### 3. 数据-议题匹配

基于数据能力，扫描 `themes/` 目录中匹配的议题：

```
这个数据能服务哪些议题？
├── 议题A: [匹配理由] — 因为数据包含[X变量]可以测度[Y概念]
├── 议题B: [匹配理由]
└── 议题C: [部分匹配] — 但缺少[Z变量]，需要融合[Z数据]
```

### 4. 竞品扫描

用 Zotero 库搜索相同数据类型 + 相似议题的论文。
> 加载 `corpus/zotero-query.md` 获取查询模式。

输出：已有多少人用类似数据做了类似问题？你的数据独有的优势（时间/粒度/变量/城市）是什么？

### 5. 如果用户已有初步问题

回到宪法，更新逻辑链中的数据环为 `confirmed`。
如果数据能力不支持原始问题 → **这是好的**：数据告诉你问题需要调整，避免了一个月后才发现做不了。

---

## 输出

1. 数据能力画像
2. 可回答的问题层级
3. 匹配的议题列表 + 匹配理由
4. Zotero 竞品扫描结果
5. **宪法写入**：逻辑链.数据来源(confirmed)、逻辑链.方法论(tentative)、竞品坐标草稿
